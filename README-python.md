# 视频去人声工具（NoVoice）

去掉视频里的人声（对白 / 演唱），**画面、字幕、章节、元数据完全不受影响**。
枪声、脚步、环境音和环绕声道从原轨保留，而不是用 AI 重建「伴奏」。

## 原理

```
原视频 ──┬─ 视频流 ──────────── 直接流复制（零重编码，逐位不变）
         ├─ 字幕 / 章节 / 元数据 ─ 原样保留
         └─ 音轨 ──> Demucs 只估计人声 ──> 原轨 − 人声 ──> 重新封装
```

- AI 只用 Meta 开源的 **Demucs**（`htdemucs` / `htdemucs_ft`）估计人声。
- 输出是「原音轨减去人声估计」：其他声音不经过模型重建。5.1/7.1 只处理前/中置，环绕和 LFE 原样留下。
- 音轨内容变了所以会重编码（立体声 AAC 320k，5.1 自动提高码率）；**视频画面不经过任何重编码**。
- 有 NVIDIA 显卡时自动用 GPU 加速；显存不足或无显卡时自动退回 CPU。

## 使用方法

### 方式一：图形界面（推荐）

双击 **`启动工具.bat`**。首次运行会自动创建虚拟环境并安装依赖（需要几分钟），
之后每次启动都是秒开。

界面里：`添加视频`（或直接把文件拖进窗口）→ `开始处理`。
输出文件自动加 `_无人声` 后缀，保存在原视频同目录。

选项说明：

| 选项 | 说明 |
|---|---|
| 标准（速度快） | `htdemucs` 做人声估计，适合日常录像 |
| 高质量（更慢） | `htdemucs_ft` 人声估计更准，对白抠得更干净，耗时约 4 倍 |
| 全部音轨都去人声 | 视频有几条音轨就处理几条（多语言/双音轨视频适用） |
| 仅第一条音轨 | 只处理第一条，其余音轨原样复制保留 |

### 方式二：命令行 / 批量

```bash
# 激活虚拟环境后
python vocal_remover.py 视频.mp4                # 输出 视频_无人声.mp4
python vocal_remover.py a.mp4 b.mkv c.mov       # 批量
python vocal_remover.py 视频.mp4 -m htdemucs_ft # 高质量模型
python vocal_remover.py 视频.mp4 -o 输出.mp4    # 指定输出路径
```

## 首次运行说明

- `启动工具.bat` 会自动完成：创建虚拟环境 → 安装依赖（有 NVIDIA 显卡装 GPU 版）→ 下载 AI 模型到 `models/` 目录（国内走 hf-mirror 镜像）→ 启动界面。之后每次启动秒开、完全离线可用。
- 命令行工具依赖 FFmpeg：`winget install Gyan.FFmpeg`（装完重开终端）。
- Demucs 官方模型源 `dl.fbaipublicfiles.com` 在部分地区无法访问，本工具优先使用本地 `models/` 目录（通过 `--repo` 传入），不依赖该网站。

## 常见问题

**Q: 画面质量会变吗？**
不会。视频流是逐位复制（`-c:v copy`）的，输出画面和原视频完全相同，不重新编码。

**Q: 字幕、多音轨会丢吗？**
不会。内嵌字幕、章节、字体附件、元数据都会保留；第二条及以后的音轨按选项原样复制。

**Q: 为什么还有一点残留人声 / 其他声音也被削了？**
人声估计不可能 100% 干净。混响很重的对白会留一点尾巴；和人声频谱重叠的枪声、技能音也可能被削一点。
可以改用「高质量」模型。当前管线已经是「原轨减人声」，不再用模型重建鼓/贝斯/其它轨。

**Q: 原来是 5.1 / 游戏录像怎么办？**
只从 FL/FR/FC 估计人声，LFE 和环绕声道不进模型，输出保持原声道数和采样率。适合 FPS 录像里保留脚步和枪声方位。

**Q: 处理速度？**
以 RTX 3050 笔记本 GPU 实测：标准模型约 2~3 倍速（10 分钟视频约 3~4 分钟），
高质量模型 `htdemucs_ft` 约慢 4 倍；纯 CPU 大约等于视频时长或更慢。
除分离外还有约 5~10 秒的模型加载开销。
